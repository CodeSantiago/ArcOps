# Design: Tools Schema — Fase 1

## Technical Approach

Flat per-tool JSON Schema files (Approach 1 from exploration). Schema validation infrastructure (`__init__.py`, `importlib.resources`, `jsonschema.Draft202012Validator`) remains unchanged. Two schema files co-exist; `tool_definitions.json` is generated by a Python script to prevent schema/training drift. Output format is OpenAI function-calling (`{"name", "arguments"}`).

## Architecture Decisions

### Decision: `instance_type` constraint

| Option | Tradeoff | Decision |
|--------|----------|----------|
| Full 300+ enum | Too large for training context | |
| Curated ~40-types enum | Maintenance burden, risk of missing new types | |
| Regex pattern `^[a-z][0-9][a-z]+\.[0-9]+[a-z]+$` | Broader acceptance, no enum maintenance | ✅ **Chosen** |

**Rationale**: Regex accepts all valid EC2 type strings (t3.xlarge, m5.2xlarge, c6g.16xlarge) without an exhaustive enum. Training teaches the model which types are real; schema bounds only the format.

### Decision: `region` constraint

**Choice**: 12-region enum: `us-east-1`, `us-east-2`, `us-west-1`, `us-west-2`, `eu-west-1`, `eu-central-1`, `eu-west-2`, `ap-southeast-1`, `ap-southeast-2`, `ap-northeast-1`, `sa-east-1`, `ca-central-1`. Shared constant between both schemas.

**Rationale**: Covers all major AWS commercial regions. Users of this tool set will almost always operate in one of these regions. Shared enum means both schemas enforce the same set — single source of truth.

### Decision: `tool_definitions.json` generation

**Choice**: Python script `scripts/generate_tool_definitions.py` reads all `.json` schema files from `schemas/`, transforms each to OpenAI function-calling format (`{name, description, parameters}`), writes `tool_definitions.json`.

**Rationale**: Auto-generation eliminates manual drift risk. Script is runnable as `uv run scripts/generate_tool_definitions.py`. The generated file is committed to the repo so the training pipeline never depends on a build step.

### Decision: No `__init__.py` changes

**Rationale**: `load_schema("create_ec2_instance")` already uses `importlib.resources` — adding `restart_database.json` to the same directory makes `load_schema("restart_database")` work with zero code changes. `tool_definitions.json` is excluded from per-tool validation since it's a different format (array, not a single-object schema).

## Data Flow

```
NL prompt (user)
    │
    ▼
LLM model (fine-tuned)
    │  outputs {"name": "create_ec2_instance", "arguments": {...}}
    ▼
load_schema(name) ──→ schema dict from .json file
    │
    ▼
validate_payload(schema, arguments) ──→ list[str] errors
    │
    ├── empty → tool call ready for execution (Fase 3+)
    └── non-empty → rejected, error messages returned
```

For training data ingestion:

```
schemas/create_ec2_instance.json ──┐
                                   ├──▶ scripts/generate_tool_definitions.py ──▶ tool_definitions.json
schemas/restart_database.json  ────┘
                                           │
                                           ▼
                                    Training pipeline consumes
                                    OpenAI function definitions
```

## Interfaces / Contracts

**Schema format** (all schemas follow this envelope):

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://example.com/cloudops-fc/schemas/{name}.json",
  "title": "{Display Name}",
  "description": "Schema for the {name} function-calling tool",
  "type": "object",
  "properties": { ... },
  "required": [...],
  "additionalProperties": false
}
```

**OpenAI function-calling entry** (in `tool_definitions.json`):

```json
{
  "name": "create_ec2_instance",
  "description": "Launch an EC2 instance in the specified region",
  "parameters": { ... }
}
```

**Validation contract** (unchanged from existing):

```python
load_schema(name: str) -> dict           # raises FileNotFoundError
validate_payload(schema: dict, payload: dict) -> list[str]  # empty = valid
```

## Testing Strategy

| Layer | What | Approach |
|-------|------|----------|
| Meta-conformance | Both schemas validate Draft 2020-12 | Extend `SCHEMA_NAMES = ["create_ec2_instance", "restart_database"]` — already parametrized |
| Valid payload EC2 | Full + required-only payloads pass `create_ec2_instance` | Use R8-S1/S2 payloads from spec |
| Valid payload RDS | Required + full payloads pass `restart_database` | New `test_valid_restart_payload`, `test_valid_restart_with_failover` |
| Malformed payloads | Missing required / wrong type / extra field / pattern mismatch / enum violation | Parametrize same test class with `(schema_name, payload_modifier_fn)` pairs covering both schemas |
| Tool definitions | Structure, equivalence with source schemas, no extra tools | `TestToolDefinitions`: 4 scenarios from spec |
| Coverage | ≥80% maintained | Existing threshold; new tests increase coverage |

## Migration / Rollout

No migration required. The schema directory is purely data files consumed at import time. Replace `create_ec2_instance.json` in-place, add new files, commit. No runtime state or database migration.
